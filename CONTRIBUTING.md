# Contributing to RenewalIQ

This is a portfolio project, but it is maintained like a real one: every change has to
pass the same gates a pull request would on a team. Thanks for reading before opening one.

## Getting a working org

Follow either option in [README.md](README.md#quick-start). For anything Apex, the scratch
org path (`./scripts/setup.sh` or `scripts/setup.ps1`) is faster and disposable. For
anything involving the LLM callout you need a Developer Edition org with a Groq key stored
in the External Credential principal — see [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

## Branching and commits

- Branch from `main`: `feature/<short-name>`, `fix/<short-name>`, `docs/<short-name>`.
- Commit messages are lowercase and typed, one line, imperative:
  `fix: run the Apex CI job on node 24`, `docs: phase 8 - coverage close-out and portfolio README`.
- Keep a pull request to one concern. A formatting sweep mixed into a logic change hides
  the logic change.
- Do not commit generated artefacts: `test-results/`, `coverage/`, `.sf/`, `.sfdx/` and
  `node_modules/` are already ignored. Screenshots belong in `docs/screenshots/`.

## The gates a pull request must pass

Run these locally before pushing. CI runs the same list, plus a scratch-org test run.

```bash
npm run lint             # ESLint over force-app/main/default/lwc
npm run prettier:verify  # Prettier over Apex, XML, LWC, Markdown, YAML
npm run test:unit        # Jest (sfdx-lwc-jest)
```

```bash
# Apex tests with coverage, then the gate that CI enforces
sf apex run test --target-org <alias> --test-level RunLocalTests \
  --code-coverage --result-format json --output-dir test-results
node scripts/ci/check-coverage.mjs test-results
```

```bash
# Static analysis (needs a JDK; Android Studio's bundled JBR works on Windows)
sf code-analyzer run --config-file config/code-analyzer.yml \
  --workspace . --rule-selector pmd:RenewalIQApex --view table
```

The gates themselves:

| Gate                    | Threshold                          | Where                           |
| ----------------------- | ---------------------------------- | ------------------------------- |
| Apex tests              | all pass, and the run is not empty | `scripts/ci/check-coverage.mjs` |
| Org-wide Apex coverage  | ≥ 90%                              | same                            |
| Per-class Apex coverage | ≥ 85%                              | same                            |
| ESLint                  | no errors                          | `.github/workflows/ci.yml`      |
| Prettier                | no diffs                           | same                            |
| Jest                    | all pass                           | same                            |
| PMD                     | 0 violations                       | same                            |

**Do not relax a gate to get a pull request through.** If a change makes coverage fall,
add a test that exercises the new branch. If a rule genuinely must be suppressed, use an
inline `// NOPMD <reason>` on the reported line and record the reason in
[docs/SECURITY.md](docs/SECURITY.md), which already lists every accepted suppression.

## Conventions worth knowing

- **One code path per fact.** A score is written only by
  `RIQ_HealthScoreRecalculator.process(Set<Id>)`. Do not add a second writer; extend the
  result object instead.
- **Bulk-safe by construction.** No SOQL or DML inside a loop. Query once per object per
  transaction, group in memory, DML once for whole lists, and use
  `Database.update(list, false, AccessLevel.SYSTEM_MODE)` where a single bad record must
  not abort the rest.
- **Configuration is Custom Metadata.** Weights, decay days, thresholds, batch size, model
  name and token cap live in `RIQ_*__mdt`. No magic numbers in Apex.
- **Access levels are explicit.** Selectors default to `USER_MODE`. If a class must run in
  `SYSTEM_MODE`, say so at the call site and explain why in the class comment.
- **A fallback must look like a fallback.** Anything generated by rules instead of the model
  is stored with `RIQ_AI_Source__c = 'Rule-based'` and badged **Rule based** in the UI.
- **Comments explain why.** The what is in the code; the comment is for the decision, the
  trade-off, or the bug that taught you the rule.
- **Tests assert behaviour.** Name the business rule in the assertion message. A test with
  no assertion, or one that only asserts "no exception", will be rejected in review.

## Reporting a bug

Open an issue using the template. Include the org type (scratch or Developer Edition), the
exact CLI command, and the log line from `RIQ_Log__c` if the app produced one. Never paste
an auth URL, an API key, or a session id — redact anything that looks like a credential.

## Security

See [docs/SECURITY.md](docs/SECURITY.md) and [.github/SECURITY.md](.github/SECURITY.md) for
how to report a vulnerability privately. Do not open a public issue for a secret leak.
